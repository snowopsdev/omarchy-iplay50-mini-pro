Design rationale, reuse plan, and boundaries

One Omarchy foundation

Dark solid surfaces, clear type, restrained theme accents, Terminal beside Browser and Files. Window and workspace actions remain available by touch and by keyboard. Navigation targets remain at least 48 logical pixels. The keyboard preserves the existing focus and modifier model; A uses a compact four-row ABC layout.

This is a shell proposal. Mock terminal and document contents show focus and system chrome only. Chromium, Files, editors, and other native applications retain their own internals. A portal picker or permission sheet only applies where the application actually uses that portal.

Focus contract

  1. A tap selects a named text field. Keys show that destination above the layout.
  2. Key presses keep that destination; one tap produces one key. Ctrl, Alt, Super, and Shift latch for one key, then release.
  3. Hide, app switch, rotation, page change, lock, or confirmation clears modifiers. Reopening Keys preserves text, not a stale modifier.
  4. Opening a shell layer pauses app typing. Closing it restores the prior app, with the keyboard hidden until requested. No click-through dismissal.

Build from existing pieces

Prefer user-owned Omarchy Quickshell plugins and existing WidgetButton, Panel, PanelSlider, ToggleSwitch, ConfirmDialog, and KeyboardPanel patterns where installed. Use Hyprland workspace/client data and fixed dispatch actions; keep the working wvkbd input engine and tablet-ui helper. No browser shell is proposed.

Use NetworkManager for actual connection state; PipeWire and MPRIS for supported audio/media; the native notification service for notification history. Qt Quick Controls provides accessible control semantics, but touchscreen, focus, and accessibility integration need device validation.

The checkout is newer than the installed Omarchy package. Component names show a reuse direction, not an API compatibility guarantee. Authentication must use an actual session-lock implementation. The HTML lock is only a storyboard.

Device truth

Physical display 1920 × 1200, scale 1.5 → 1280 × 800 logical. Portrait is 800 × 1280. Rotation is working. Speaker audio and H264 decode have evidence; microphone/headset/Bluetooth audio, calibrated battery percentage, touch unlock, and suspend remain unvalidated. No battery percentage, runtime estimate, biometric claim, or working Sleep button appears here.
